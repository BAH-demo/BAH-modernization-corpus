## SBOM Generation Commands

### Java (Maven) Systems
```bash
mvn org.cyclonedx:cyclonedx-maven-plugin:2.7.11:makeAggregateBom \
  -DoutputFormat=json -DoutputName={system}-sbom
```

### Java (Gradle) Systems
```bash
# Add to build.gradle:
# plugins { id 'org.cyclonedx.bom' version '1.7.4' }
gradle cyclonedxBom
```

### Python Systems
```bash
cyclonedx-py requirements requirements.txt --of json -o {system}-sbom.json
```

### .NET Systems
```bash
dotnet tool install --global CycloneDX
dotnet CycloneDX {solution}.sln -o {system}-sbom.json -j
```

## Compliance Notes

- **EO 14028 Section 4(e):** Requires SBOMs for all software delivered to the federal government
- **NIST SP 800-218:** SBOM generation should be integrated into CI/CD pipelines
- **NTIA Minimum Elements:** All generated SBOMs include supplier name, component name, version, unique identifier (PURL), and dependency relationships
- **Update Cadence:** SBOMs should be regenerated on every release and when dependencies change
- **CI/CD Integration:** GitHub Actions workflows include `cyclonedx` generation steps for automated SBOM updates
